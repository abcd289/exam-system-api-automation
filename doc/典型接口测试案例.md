# 典型接口测试案例

本文档选取学之思在线教育考试系统中的用户管理模块，展示接口测试设计、接口关联、动态参数提取及数据库校验的实际应用。

## 一、用户管理模块测试概述

用户管理模块主要涉及用户查询、新增、编辑、状态修改和删除等业务操作。

本模块重点验证：

- 用户新增、编辑、删除等核心业务功能是否正常。
- 接口是否能够正确处理异常参数。
- 登录鉴权是否有效，未登录状态下是否能够限制访问。
- 不同接口之间能否正确传递动态参数。
- 接口执行后数据库中的数据是否符合预期。

## 二、典型接口测试案例

### 2.1 新增用户接口

**接口信息**

| 项目 | 内容 |
|---|---|
| 接口名称 | 新增用户 |
| 请求方式 | POST |
| 请求地址 | `/api/admin/user/edit` |
| 请求鉴权 | Cookie（JSESSIONID） |
| 核心参数 | userName、password、realName、role、status |

**测试场景**

| 编号 | 测试场景 | 预期结果 |
|---|---|---|
| 1 | 输入合法用户信息 | 新增用户成功 |
| 2 | 用户名为空 | 提示用户名不能为空 |
| 3 | 使用已存在的用户名 | 提示用户已存在 |

**测试实现**

新增用户和编辑用户共用同一个接口，通过请求参数中的 `id` 区分操作：

- 新增用户时，`id` 设置为 `null`。
- 编辑用户时，`id` 设置为已有用户 ID。

新增成功后，从响应 JSON 中提取用户 ID，供后续编辑、查询和删除接口使用。

JSON 提取配置示例：

```json
{
    "user_id": "$.response.id"
}
```

### 2.2 编辑用户接口

**接口信息**

| 项目 | 内容 |
|---|---|
| 接口名称 | 编辑用户 |
| 请求方式 | POST |
| 请求地址 | `/api/admin/user/edit` |
| 请求鉴权 | Cookie（JSESSIONID） |
| 核心参数 | id、userName、realName、role、status |

**测试场景**

| 编号 | 测试场景 | 预期结果 |
|---|---|---|
| 1 | 编辑已存在的用户 | 修改用户成功 |
| 2 | 使用不存在的用户 ID | 根据实际接口规则验证处理结果 |
| 3 | 修改用户基本信息 | 返回成功，数据库数据同步更新 |

**测试实现**

编辑用户时，使用新增用户接口提取的 `user_id` 作为动态参数。

请求参数示例：

```json
{
    "id": {{user_id}},
    "userName": "student1000",
    "realName": "测试学生1",
    "role": 1,
    "status": 1
}
```

通过接口响应断言验证编辑结果，并执行 SQL 查询数据库中的用户信息。

数据库校验 SQL：

```sql
SELECT real_name
FROM t_user
WHERE id = {{user_id}};
```

预期结果：`测试学生1`。

### 2.4 删除用户接口

**接口信息**

| 项目 | 内容 |
|---|---|
| 接口名称 | 删除用户 |
| 请求方式 | POST |
| 请求地址 | `/api/admin/user/delete/{{user_id}}` |
| 请求鉴权 | Cookie（JSESSIONID） |

**测试场景**

| 编号 | 测试场景 | 预期结果 |
|---|---|---|
| 1 | 删除已存在的用户 | 删除操作成功 |
| 2 | 删除后查询数据库 | 用户删除标记发生变化 |

**数据库校验 SQL**

```sql
SELECT deleted
FROM t_user
WHERE id = {{user_id}};
```

该系统采用逻辑删除方式，删除操作后记录仍然保留在数据库中，通过 `deleted` 字段标记删除状态。

预期结果：`True`。

## 三、接口关联测试

在用户管理模块中，新增、编辑、修改状态、删除等接口存在业务上的数据依赖。

通过动态数据提取实现多个接口之间的关联，避免在后续请求中手动填写固定用户 ID。

**接口关联流程：**

1. 管理员登录，提取响应中的 JSESSIONID。
2. 新增用户，在响应 JSON 中提取用户 ID。
3. 编辑用户，将提取的用户 ID 传入请求参数。
4. 查询数据库，验证用户信息是否更新。
5. 修改用户状态，使用相同用户 ID 完成操作。
6. 删除用户，使用相同用户 ID 执行删除。
7. 查询数据库，验证逻辑删除标记。

**关联关系示意：**

```text
管理员登录
    |
    | 提取 JSESSIONID
    v
新增用户
    |
    | JSON 提取 user_id
    v
编辑用户
    |
    | SQL 校验 real_name
    v
修改用户状态
    |
    | SQL 校验 status
    v
删除用户
    |
    | SQL 校验 deleted
    v
完成接口关联测试
```
