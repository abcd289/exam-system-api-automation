# 典型接口测试案例

本文档选取学之思在线教育考试系统中的用户管理模块，展示接口测试设计、接口关联、动态参数提取及数据库校验的实际应用。

## 一、用户管理模块测试概述

用户管理模块主要涉及用户查询、新增、编辑、状态修改和删除等业务操作。

本模块重点验证：

- 用户新增、编辑、删除等核心业务功能是否正常。
- 接口是否能够正确处理异常参数。
- 登录鉴权是否有效，未登录状态下是否能够限制访问。
- 不同接口之间能否正确传递动态参数。
- 接口执行后数据库中的数据是否符合预期。

## 二、典型接口测试案例

### 2.1 新增用户接口

**接口信息**

| 项目 | 内容 |
|---|---|
| 接口名称 | 新增用户 |
| 请求方式 | POST |
| 请求地址 | `/api/admin/user/edit` |
| 请求鉴权 | Cookie（JSESSIONID） |
| 核心参数 | userName、password、realName、role、status |

**测试场景**

| 编号 | 测试场景 | 预期结果 |
|---|---|---|
| 1 | 输入合法用户信息 | 新增用户成功 |
| 2 | 用户名为空 | 提示用户名不能为空 |
| 3 | 使用已存在的用户名 | 提示用户已存在 |

**测试实现**

新增用户和编辑用户共用同一个接口，通过请求参数中的 `id` 区分操作：

- 新增用户时，`id` 设置为 `null`。
- 编辑用户时，`id` 设置为已有用户 ID。

新增成功后，从响应 JSON 中提取用户 ID，供后续编辑、查询和删除接口使用。

JSON 提取配置示例：

```json
{
    "user_id": "$.response.id"
}
```

### 2.2 编辑用户接口

**接口信息**

| 项目 | 内容 |
|---|---|
| 接口名称 | 编辑用户 |
| 请求方式 | POST |
| 请求地址 | `/api/admin/user/edit` |
| 请求鉴权 | Cookie（JSESSIONID） |
| 核心参数 | id、userName、realName、role、status |

**测试场景**

| 编号 | 测试场景 | 预期结果 |
|---|---|---|
| 1 | 编辑已存在的用户 | 修改用户成功 |
| 2 | 使用不存在的用户 ID | 根据实际接口规则验证处理结果 |
| 3 | 修改用户基本信息 | 返回成功，数据库数据同步更新 |

**测试实现**

编辑用户时，使用新增用户接口提取的 `user_id` 作为动态参数。

请求参数示例：

```json
{
    "id": {{user_id}},
    "userName": "student1000",
    "realName": "测试学生1",
    "role": 1,
    "status": 1
}
```

通过接口响应断言验证编辑结果，并执行 SQL 查询数据库中的用户信息。

数据库校验 SQL：

```sql
SELECT real_name
FROM t_user
WHERE id = {{user_id}};
```

预期结果：`测试学生1`。

### 2.4 删除用户接口

**接口信息**

|---|---|
| 接口名称 | 删除用户 |
| 请求方式 | POST |

## 三、接口关联测试

在用户管理模块中，新增、编辑、修改状态、删除等接口存在业务上的数据依赖。

通过动态数据提取实现多个接口之间的关联，避免在后续请求中手动填写固定用户 ID。

**接口关联流程：**

1. 管理员登录，提取响应中的 JSESSIONID。
2. 新增用户，在响应 JSON 中提取用户 ID。
3. 编辑用户，将提取的用户 ID 传入请求参数。
4. 查询数据库，验证用户信息是否更新。
5. 修改用户状态，使用相同用户 ID 完成操作。
6. 删除用户，使用相同用户 ID 执行删除。
7. 查询数据库，验证逻辑删除标记。

**关联关系示意：**

```text
管理员登录
    |
    | 提取 JSESSIONID
    v
新增用户
    |
    | JSON 提取 user_id
    v
编辑用户
    |
    | SQL 校验 real_name
    v
修改用户状态
    |
    | SQL 校验 status
    v
删除用户
    |
    | SQL 校验 deleted
    v
完成接口关联测试
```

## 四、接口自动化实现要点

本项目基于 Python + Requests + Pytest 搭建接口自动化测试框架，使用 Excel 管理测试用例和测试数据，实现用户管理模块核心接口的自动化回归测试。

### 4.1 Excel 数据驱动

使用 openpyxl 读取 Excel 测试用例，将接口请求信息、测试数据、预期结果及数据提取规则进行统一管理。

主要字段包括：

| 字段 | 作用 |
|---|---|
| method、path | 请求方式、接口路径 |
| headers、params | 请求头、URL 参数 |
| data、json | 请求表单数据、JSON 参数 |
| check、expected | 响应校验字段、预期结果 |
| jsonExData | JSON 响应数据提取规则 |
| cookieExData | Cookie 提取规则 |
| sql_check、sql_expected | 数据库校验 SQL、预期结果 |

通过 Excel 管理不同接口的测试数据，减少测试代码与测试数据之间的耦合，方便后续增加和维护测试用例。

### 4.2 Cookie 动态提取与鉴权

管理员登录成功后，从响应 Cookie 中提取 JSESSIONID，并保存到公共变量中。

后续请求通过请求头传递 Cookie：

```json
{
    "Cookie": "JSESSIONID={{JSESSIONID}}"
}
```

通过动态传递登录凭证，实现用户管理模块多个接口的登录态复用。

同时设计未登录状态下查询用户列表的测试用例，验证接口是否能够正确拦截未登录请求。

### 4.3 JSON 动态参数提取与接口关联

新增用户成功后，响应数据中包含新用户的 ID。框架使用 JSONPath 提取该字段，并保存为公共变量：

```json
{
    "user_id": "$.response.id"
}
```

后续编辑、修改状态和删除接口通过 Jinja2 模板引用动态变量：

```json
{
    "id": {{user_id}},
    "userName": "student1000",
    "realName": "测试学生1",
    "role": 1,
    "status": 1
}
```

避免在后续接口中手动填写固定 ID，使多个接口能够围绕同一条测试数据完成连续业务操作。

### 4.4 响应断言与数据库校验

框架根据 Excel 中配置的校验字段和预期结果，对接口响应进行断言，验证接口是否返回符合预期的结果。

对于需要验证数据库状态的场景，使用 PyMySQL 连接 MySQL 数据库，执行 SQL 查询并与预期结果进行比对。

例如：

**编辑用户后校验用户姓名：**

```sql
SELECT real_name
FROM t_user
WHERE id = {{user_id}};
```

预期结果：`测试学生1`。

**修改用户状态后校验状态字段：**

```sql
SELECT status
FROM t_user
WHERE id = {{user_id}};
```

预期结果：`2`。

**删除用户后校验逻辑删除标记：**

```sql
SELECT deleted
FROM t_user
WHERE id = {{user_id}};
```

预期结果：`True`。

通过接口响应断言和数据库查询相结合，验证接口执行结果与数据库实际数据是否一致。

### 4.5 Allure 测试报告

使用 Allure 记录接口自动化执行过程，将测试用例名称、请求信息、响应结果、断言结果及数据库校验过程纳入测试报告，便于查看用例执行情况和定位失败原因。

## 五、典型接口关联执行流程

用户管理模块的自动化测试围绕同一条测试用户数据展开，整体执行流程如下：

```text
管理员登录
    |
    | Cookie 提取 JSESSIONID
    v
新增用户
    |
    | JSONPath 提取 user_id
    v
编辑用户
    |
    | 响应断言 + SQL 校验 real_name
    v
修改用户状态
    |
    | 响应断言 + SQL 校验 status
    v
删除用户
    |
    | 响应断言 + SQL 校验 deleted
    v
完成用户管理业务流程测试
```

该流程体现了接口之间的动态参数传递，以及接口执行结果与数据库数据的联合验证。

## 六、测试案例总结

通过用户管理模块的接口测试实践，完成了以下测试内容：

1. **接口功能验证：** 覆盖用户列表查询、新增、编辑、修改状态和删除等核心接口。
2. **异常场景验证：** 覆盖未登录访问、用户名为空、用户名重复等场景。
3. **接口关联验证：** 登录后提取 JSESSIONID，新增用户后提取用户 ID，并将动态参数传递给后续接口。
4. **数据库验证：** 通过 SQL 查询验证用户信息修改、状态变化及逻辑删除结果。
5. **自动化回归：** 将核心正向业务流程编写为 Pytest 自动化用例，使用 Excel 管理测试数据，通过 Allure 查看执行结果。

通过该案例，实践了从接口测试设计、接口关联、动态数据提取到数据库校验的完整测试流程。
