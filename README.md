# 在线教育考试系统接口自动化测试

## 一、项目简介

本项目基于 Python + Pytest + Requests 搭建，针对学之思在线教育考试系统开展接口功能测试与接口自动化测试实践。

项目采用 Excel 数据驱动的方式管理测试用例，实现测试数据与测试代码分离，并基于 Pytest 搭建自动化测试执行框架，对 HTTP 请求、接口鉴权、响应断言、动态数据提取及数据库校验等功能进行封装。

通过对接口请求方法、测试用例解析、数据提取、断言及报告生成等模块进行封装，提高自动化测试的可维护性和执行效率。

项目主要涉及学校管理端和学生端的业务接口，重点关注用户管理、学科管理、试卷管理、考试任务、考试记录等业务场景。

## 二、项目技术栈

| 技术 | 应用说明 |
|---|---|
| Python | 自动化测试脚本开发 |
| Pytest | 测试用例组织、参数化及执行管理 |
| Requests | HTTP 接口请求与响应处理 |
| OpenPyXL | Excel 测试用例读取 |

## 三、项目测试范围

### 3.1 学校管理端

围绕学校管理端主要业务模块开展接口测试：

- 用户管理：用户新增、编辑、删除、分页查询等。
- 学科管理：学科新增、修改、删除及查询。
- 试卷管理：试卷信息维护、试卷查询及相关数据校验。
- 考试任务：固定试卷任务、时间窗口试卷任务等业务场景。
- 成绩管理：考试成绩相关查询与数据验证。

### 3.2 学生端

围绕学生端主要业务模块开展接口测试：

- 首页：相关信息查询。
- 试卷中心：试卷信息查询。
- 考试记录：考试记录查询。
- 错题本：错题信息查询。
- 任务中心：考试任务查询及相关业务接口。

## 四、自动化测试框架设计

项目采用分层封装的方式组织代码，将测试用例、测试数据、配置文件和公共方法进行分离。

### 4.1 Excel 数据驱动

使用 OpenPyXL 读取 Excel 测试用例，通过参数化方式将测试数据传递给 Pytest 测试方法。

主要实现：

- 将接口测试数据与测试代码分离。
- 通过 Excel 管理接口名称、请求方式、请求路径、请求参数及预期结果。
- 支持不同请求方式和不同测试场景。
- 通过测试数据控制正向、异常及边界场景。
- 减少重复编写测试脚本，提高用例维护效率。

### 4.2 HTTP 请求封装

基于 Requests 封装公共请求方法，统一处理接口请求。

主要实现：

- 支持 GET、POST、PUT、DELETE 等常见请求方式。
- 统一处理请求 URL、请求头、请求参数和请求体。
- 使用 Session 管理会话及 Cookie。
- 统一处理接口响应，方便后续断言和数据提取。

### 4.3 接口鉴权与 Cookie 管理

针对系统登录后的接口鉴权机制，封装 Cookie 提取和传递逻辑。

主要实现：

- 从登录接口响应中提取 Cookie。
- 将提取的 Cookie 保存到公共变量中。
- 后续请求自动携带对应的 Cookie。
- 实现登录接口与需要身份认证的业务接口之间的关联。

### 4.4 动态数据提取

针对接口之间存在数据依赖的场景，封装不同类型的数据提取方法。

主要包括：

- JSON 提取：从接口响应 JSON 数据中提取指定字段。
- Cookie 提取：从响应 Cookie 中提取会话信息。
- SQL 提取：通过数据库查询获取后续接口需要使用的数据。

提取后的数据保存为公共变量，并通过动态变量替换机制传递给后续接口，实现关联接口的连续执行。

### 4.5 接口断言

封装公共断言方法，对接口执行结果进行验证。

主要验证内容：

- HTTP 响应状态。
- 响应业务状态码。
- 响应内容及预期字段。
- 实际响应结果与 Excel 预期结果是否一致。

通过统一断言方法，减少重复代码，提高测试结果判断的一致性。

### 4.6 MySQL 数据库校验

使用 PyMySQL 连接 MySQL 数据库，对接口执行后的数据库数据进行校验。

主要实现：

- 执行 SQL 查询，获取数据库实际数据。
- 校验接口操作后数据库记录是否符合预期。
- 验证新增、修改等业务操作的数据变化。
- 支持通过 SQL 查询提取后续接口需要使用的动态数据。

通过接口响应结果与数据库实际数据相结合，提高测试结果验证的完整性。

### 4.7 Allure 测试报告

集成 Allure 测试报告，对自动化测试执行过程进行记录和展示。

主要实现：

- 展示测试用例执行结果。
- 统计测试用例通过及失败情况。
- 记录测试步骤和断言信息。
- 辅助分析接口执行失败的原因。

## 六、环境准备与安装

### 6.1 环境要求

- Python 3.x
- MySQL
- Java 环境（用于 Allure 报告相关工具）
- Allure Commandline（如需通过命令行生成及查看 HTML 报告）

### 6.2 获取项目

```bash
git clone https://github.com/abcd289/xzs-api-test.git
```

进入项目根目录：

```bash
cd xzs-api-test
```

### 6.3 安装项目依赖

```bash
pip install -r requirements.txt
```

### 6.4 配置运行环境

复制 `.env.example` 文件，在项目根目录创建本地 `.env` 文件，并根据实际测试环境填写配置。

配置示例：

```text
BASE_URL=http://127.0.0.1:8000

DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=xzs
DB_USER=root
DB_PASSWORD=your_password
```

根据实际情况修改服务地址、数据库地址、数据库名称及账号密码。

注意：`.env` 文件用于存储本地环境配置，不应上传到 GitHub。

## 七、项目运行方式

在项目根目录下执行：

```bash
python run.py
```

项目通过统一运行入口启动 Pytest 测试流程，读取 Excel 测试数据并执行对应的接口自动化测试用例。

## 八、测试执行与报告

项目集成 Allure 测试报告，用于展示自动化测试执行情况。

报告主要包含：

- 测试用例总数及执行结果。
- 测试用例通过、失败等统计信息。
- 测试步骤执行情况。
- 失败用例的相关信息。
- 接口断言结果。

可结合 Allure 报告定位失败用例，分析接口响应、参数传递及数据库校验等环节的问题。

## 九、项目实践与技术要点

通过本项目实践，完成了以下测试工作：

1. **接口功能测试：** 根据业务需求设计正向、异常及边界测试场景，验证接口功能和业务规则。
2. **接口自动化测试：** 基于 Pytest + Requests 搭建接口自动化测试框架，实现 Excel 数据驱动。
3. **接口关联：** 通过 JSON、Cookie 和 SQL 数据提取，实现多接口之间的动态参数传递。
4. **接口鉴权：** 处理登录后的 Cookie 获取、保存及后续请求传递。
5. **数据库校验：** 使用 PyMySQL 连接 MySQL，验证接口执行后的数据库数据。
6. **测试报告：** 集成 Allure，记录测试用例执行情况及测试步骤。
7. **代码管理：** 使用 Git 进行版本管理，并将项目托管至 GitHub。
